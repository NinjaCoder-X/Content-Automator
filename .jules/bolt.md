## 2024-05-24 - Database Query Offloading & Memory Anti-pattern
**Learning:** In the codebase, it is common to fetch full database tables into application memory to perform aggregations (using `.filter(...).length`) or list filtering. This can quickly cause excessive memory consumption and high network/DB transfer times. Also, when using Drizzle `sql` aggregations (e.g. conditional sum with case statements), it will return `null` instead of `0` when no rows match.
**Action:** Always offload computational work and filtering to the database. Use Drizzle ORM's native aggregations (e.g., `count()`, `.groupBy()`) and conditional `sum` wrapped in `coalesce` to default to 0 (`sql<number>cast(coalesce(sum(case when ... then 1 else 0 end), 0) as integer)`). Also push down list endpoint filters via `where` clauses using `and()` / `eq()` instead of performing `.filter()` in memory.
