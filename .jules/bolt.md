## 2024-10-24 - Database Aggregation Anti-pattern
**Learning:** Found a performance bottleneck specific to this architecture: Fetching full tables into memory to perform aggregations (e.g., `.filter().length` or `.reduce()`) instead of using SQL aggregation functions. It scales linearly `O(n)` in memory and data transfer, making endpoints slow as DB grows. When doing conditional sums using Drizzle `sql` (like `sql<number>cast(sum(case when ...))`), we must wrap the statement in `coalesce(..., 0)` to prevent returning `null` when no rows match, guaranteeing a correct integer response.
**Action:** Always offload computation to the database using Drizzle ORM's native SQL aggregation functions (`count()`, conditional `SUM(CASE WHEN...)`, and `.groupBy()`). Offloading this correctly utilizes indexing and keeps memory constant.
